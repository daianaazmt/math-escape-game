СТАТУС: исходники доработаны, проект ещё не опубликован.

Подключение выполняется после предоставления доступа к Firebase и GitHub.
1. Создать НОВЫЙ проект math-escape-10 на Spark. Не менять soch-battle-grade10.
2. Создать Firestore в production mode, выбрать регион до создания базы.
3. Включить Authentication: Anonymous и Email/Password.
4. Зарегистрировать Web App и перенести её реальные параметры в config.js.
5. Создать учётную запись учителя с паролем, выбранным владельцем. Пароль не сохранять в репозитории.
6. В консоли Firestore создать teachers/<UID учителя> с полем role: teacher. Этот документ недоступен для записи из приложения. Не использовать email как единственную проверку роли.
7. Опубликовать firestore.rules. Файл в GitHub сам по себе правила НЕ применяет.
8. Добавить daianaazmt.github.io в Authorized domains.
9. Обновить существующий репозиторий daianaazmt/math-escape-game. В Settings / Pages выбрать GitHub Actions; workflow включён в архив.
10. Проверить опубликованные страницы и несколько независимых анонимных сессий, запрет чтения и изменения чужих записей, запрет list и записи teachers учениками.

Проверено командой node tests/game.cjs: 13 уравнений и их корни, полный проход, финальное слово, неверный код, две ошибки и дополнительное задание, штрафы, однократная подсказка, неверный формат, таймаут, фиксация итогового времени. Это тест логики с имитацией DOM, не браузерная проверка.
НЕ проверены: компиляция правил эмулятором, реальные Firebase Auth/Firestore, одновременные подключения, CSV в Excel, мобильный браузер, GitHub Pages.

Попытка восстанавливается при обновлении той же вкладки; часы продолжают идти в фоне. Закрытие вкладки может удалить локальную попытку, результат в Firestore сохраняется. Каждая новая попытка — отдельная строка в панели. Данные отправляются при действиях и каждые 12 секунд. При отсутствии связи отображается предупреждение.

Ограничения: клиентская игра содержит проверку ответов в JavaScript. Правила изолируют данные учеников, но не доказывают честность введённого собственного прогресса. Для экзаменационной защиты потребуется серверная проверка. Панель считает попытки, поэтому повторная игра ученика добавляет строку. Не включены платные сервисы.
